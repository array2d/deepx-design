# 02 — 委托协议

> kvcpu 与 rwir-backend 之间的 kvspace 任务交接协议。

## 协议总览

```
kvcpu                               kvspace                         rwir-backend
─────                               ───────                         ────────────
│                                                                       │
│ 1. Select(opcode) → backend                                           │
│                                                                       │
│ 2. resolveParams(inst) → 参数绝对路径                                  │
│    buildTask → RwirTask JSON                                          │
│                                                                       │
│ 3. kv.Notify(cmd_queue, task_json) ────→ cmd queue                    │
│                                                                       │
│ 4. vthread.Set(pc, "wait")                                            │
│                                                                       │
│                                                                   5. Watch 触发
│                                                                      parse RwirTask
│                                                                      ↓
│                                                                   6. 执行
│                                                                      (GPU kernel /
│                                                                       HTTP API /
│                                                                       agent loop)
│                                                                      ↓
│                                                                   7. 写结果到 kvspace
│                                                                      (output paths)
│                                                                      ↓
│                                                                   8. kv.Notify(done_key,
│                                                                      result_json)
│                                                                      │
│ 9. vthread.WaitDone() ← Watch ────── done_key ───────────────────────┘
│    → 读 result，推进 PC                                                │
│                                                                       │
▼ 继续执行                                                               ▼ 回到 Watch 循环
```

## 命令队列

后端命令队列路径：`/sys/rwir-backend/<name>/cmd`

kvcpu 通过 `kv.Notify` 投递任务：

```go
cmdQueue := keytree.SysRwirBackendCmd(backend)
kv.Notify(cmdQueue, kvspace.NewChar(taskJSON))
```

后端通过 `kv.Watch` 消费：

```go
for {
    raw := kv.Watch(cmdQueue, 0) // 0 = 无限等待
    task := parseTask(raw.String())
    result := execute(task)
    kv.Notify(doneKey, result.toJSON())
}
```

Notify/Watch 的语义（继承自 kvspace Redis 实现的 BLPOP/LPUSH）：
- **MPMC 队列**：多个生产者可并发 Notify，多个消费者可并发 Watch，每条消息恰好被一个消费者取走
- **阻塞语义**：Watch 在队列空时阻塞，有消息时立即返回
- **无消息丢失**：Notify 在无 Watch 等待者时保留消息在队列中

## RwirTask 格式

```json
{
  "request_id": "rwir:llm_worker:7:42",
  "vtid": "7",
  "pc": "/vthread/7/[3,0]",
  "opcode": "tensor.matmul",
  "inputs": [
    {
      "key": "/vthread/7/[0,0]/a",
      "dtype": "float16",
      "shape": [512, 256],
      "address": {
        "node": "n1",
        "device": "gpu0",
        "ptr": 140285768000000,
        "byte_size": 262144
      }
    }
  ],
  "outputs": [
    {
      "key": "/vthread/7/[0,0]/c",
      "dtype": "float16",
      "shape": [512, 512]
    }
  ],
  "params": {
    "transpose_a": false,
    "transpose_b": true
  }
}
```

### 字段说明

| 字段 | 必须 | 说明 |
|------|------|------|
| `request_id` | 是 | 全局唯一标识，格式 `rwir:<backend>:<vtid>:<seq>` |
| `vtid` | 是 | 发起委托的虚线程 ID |
| `pc` | 是 | 发起委托时的 PC（后端完成后 kvcpu 从此推进） |
| `opcode` | 是 | rwir 操作码 |
| `inputs` | 否 | 读参解析结果（kvspace 绝对路径 + dtype/shape/address） |
| `outputs` | 否 | 写参解析结果（kvspace 绝对路径，dtype/shape 从 rwir 声明推断） |
| `params` | 否 | 额外参数（字面量、配置项） |

### request_id 格式

```
rwir:<backend_name>:<vtid>:<seq>

例：
  rwir:op-gpu:7:42        — op-gpu 后端执行 vthread 7 的第 42 个委托
  rwir:llm_worker:7:15    — llm_worker 后端执行 vthread 7 的第 15 个委托
  rwir:agent_pool:7:3     — agent_pool 后端执行 vthread 7 的第 3 个委托
```

`seq` 是 vthread 级别的委托序号（单调递增），由 kvcpu 在委托时分配。

## 参数解析：从 rwir 到绝对路径

rwir 指令的读写参在 lower 后可能是裸标识符（局部变量）、字面量、或绝对路径。委托前必须全部解析为 **kvspace 绝对路径**——后端无帧上下文。

```go
func resolveParams(kv kvspace.KVSpace, vtid, frameRoot string, inst *rwir.Rwir) (inputs, outputs []ParamRef) {
    for _, r := range inst.Reads {
        if isLiteral(r.Name) {
            // 字面量 → 放入 params，不放入 inputs
            continue
        }
        key := r.Name
        if !isAbsolute(r.Name) {
            key = resolveLocalVar(kv, frameRoot, r.Name) // 帧内变量 → 绝对路径
        }
        meta := readTensorMeta(kv, key) // dtype/shape/address
        inputs = append(inputs, ParamRef{Key: key, ...meta})
    }
    for _, w := range inst.Writes {
        key := w.Name
        if !isAbsolute(w.Name) {
            key = resolveWriteSlot(kv, frameRoot, w.Name)
        }
        outputs = append(outputs, ParamRef{Key: key})
    }
    return
}
```

关键：**后端只看到 kvspace 绝对路径**。后端 Get 输入、Set 输出，完全不感知帧/scope/局部变量的 kvlang 概念。

### address 字段

`address` 用于传递扩展存储句柄（GPU 显存指针、shm 名称等）。kvspace 元存不持有 tensor 原始数据，`address` 告知后端如何访问实际数据：

```json
"address": {
  "node": "n1",
  "device": "gpu0",
  "ptr": 140285768000000,
  "byte_size": 262144
}
```

对于 API/Agent 类后端，`address` 通常为空——它们的输入输出是 kvspace 中的标量值。

## 完成信号

后端完成后，Notify 完成信号：

```
/done/rwir/<request_id>
```

完成信号格式：

```json
{
  "request_id": "rwir:op-gpu:7:42",
  "status": "ok",
  "outputs_updated": [
    {"key": "/vthread/7/[0,0]/c", "dtype": "float16", "shape": [512, 512]}
  ]
}
```

错误：

```json
{
  "request_id": "rwir:op-gpu:7:42",
  "status": "error",
  "error": {
    "code": "GPU_OOM",
    "message": "out of memory: requested 2GB, available 1.5GB"
  }
}
```

### kvcpu 侧等待

```go
func Delegate(ctx context.Context, kv kvspace.KVSpace, vtid, pc string, inst *rwir.Rwir) error {
    backend, err := Select(ctx, kv, inst.Opcode)
    if err != nil {
        return fmt.Errorf("delegate %s: %w", inst.Opcode, err)
    }
    
    task := buildRwirTask(kv, vtid, pc, inst)
    doneKey := keytree.DoneRwir(task.RequestID)
    
    // 投递任务
    kv.Notify(keytree.SysRwirBackendCmd(backend), kvspace.NewChar(task.ToJSON()))
    
    // 标记等待
    vthread.Set(ctx, kv, vtid, pc, "wait")
    
    // 阻塞等待完成
    raw := kv.Watch(doneKey, timeoutFor(inst.Opcode))
    if raw.String() == "" {
        vthread.SetError(ctx, kv, vtid, pc, "delegate timeout")
        return fmt.Errorf("delegate %s: timeout", inst.Opcode)
    }
    
    var result RwirResult
    json.Unmarshal([]byte(raw.String()), &result)
    if result.Status == "error" {
        vthread.SetError(ctx, kv, vtid, pc, result.Error.Message)
        return fmt.Errorf("delegate %s: %s", inst.Opcode, result.Error.Message)
    }
    
    // 成功：推进 PC
    vthread.Set(ctx, kv, vtid, rwir.NextPC(pc), "running")
    return nil
}
```

## 超时策略

不同类别后端有不同超时：

| 类别 | 默认超时 | 理由 |
|------|---------|------|
| compute | 30s | GPU kernel 执行，毫秒级常态，30s 兜底 |
| api | 120s | LLM API 调用，秒~十秒级，2min 覆盖重试 |
| agent | 300s | sub-agent 可能多轮 tool use，5min 默认 |

超时后 kvcpu 调用 `vthread.SetError`，不重试——重试策略由上层 kvlang 代码决定（可 `if err { retry() }`）。

## 幂等性

`request_id` 保证后端可以安全重试（后端崩溃后 kvspace 中仍有该 request_id 的 done 信号，重新 Watch 即可）。

**后端实现要求**：同 `request_id` 重复到达时（后端崩溃重启后重新 Watch 到旧消息），检查 `done_key` 是否已存在——若存在则跳过执行，直接返回已有结果。

## 与现有 dispatch.Compute 的对比

| | dispatch.Compute | rwir-backend Delegate |
|--|-----------------|----------------------|
| 完成信号 | vthread `.status` Del+Notify | `/done/rwir/<request_id>` Notify |
| 等待方式 | `vthread.WaitDone` (Watch .status) | `kv.Watch(done_key)` |
| 超时 | 硬编码 30s | 按类别配置 |
| 队列路径 | `/sys/op/<backend>/<n>/cmd` | `/sys/rwir-backend/<name>/cmd` |
| opcode 筛选 | 硬编码 `tensor.` 前缀 | Select 查 `/sys/rwir-backend/<name>/op/` |

关键改进：完成信号从 vthread `.status` 解耦到独立 `done_key`。原因：vthread `.status` 是线程级生命周期——同一个 vthread 可能连续发起多个委托，用 `.status` 做完成信号会在并发委托时冲突。独立 `done_key`（每个 request 一个）天然支持并发委托。

## keytree 路径常量

```go
// keytree/sys.go

func DoneRwirRoot() string {
    return "/done/rwir"
}
func DoneRwir(requestID string) string {
    return DoneRwirRoot() + "/" + requestID
}
```
