# 01 — 后端注册与发现

## 注册路径

后端进程启动时在 `/sys/rwir-backend/<name>/` 下自注册：

```
/sys/rwir-backend/<name>/
├── status         = string:"ready"      # ready | busy | offline
├── load           = float:0.3           # [0,1] 当前负载
├── pid            = int:12345           # 进程 ID
├── started_at     = int:1690000000      # unix timestamp
├── heartbeat      = int:1690000005      # 最后心跳时间（每 5s 更新）
├── category/                          # 能力声明（至少一个 category）
│   ├── compute                        # 计算类后端（op-gpu 等）
│   ├── api                            # API 封装类后端（LLM 等）
│   └── agent                          # Agent 封装类后端
└── op/                                # 支持的 rwir opcode 列表
    ├── tensor.matmul                  # 存在即支持
    ├── tensor.add
    ├── llm.chat
    └── agent.search
```

### 注册时序

```
1. 后端进程启动
2. 自检：设备就绪（GPU context / API key 有效 / agent 配置齐全）
3. kv.Set("/sys/rwir-backend/<name>/status", "ready")
4. kv.Set("/sys/rwir-backend/<name>/category/<cat>", "")
5. for each supported opcode:
     kv.Set("/sys/rwir-backend/<name>/op/<opcode>", meta_json)
6. 进入 Watch 循环
```

### 注销

```
进程退出前:
  kv.Set("/sys/rwir-backend/<name>/status", "offline")
  # 不 DelTree——保留注册记录供排障

异常退出:
  heartbeat 超时 → kvcpu 侧标记为 offline（见下文"发现"）
```

## 发现：Select() 算法

kvcpu 在遇到需要委托的 rwir 时，调用 `Select(opcode)` 选择后端实例：

```
Select(opcode):
  1. candidates = []
  2. for backend in kv.List("/sys/rwir-backend/"):
       if kv.Exists("/sys/rwir-backend/<backend>/op/<opcode>"):
         if not heartbeat_timeout(backend):
           candidates.append(backend)
  3. if candidates empty → error("no backend for opcode")
  4. 按 load 升序排列 candidates
  5. 返回 load 最低者
```

与现有 `dispatch.Select` 的关键差异：
- 现有 `Select` 查询 `/sys/op/<backend>/func/<opname>`，按 `backend/instance` 两级路由
- 新 `Select` 查询 `/sys/rwir-backend/<name>/op/<opcode>`，**扁平一级路由**——后端名即实例名
- 原因：rwir-backend 比 op-level backend 更"重"，通常一个后端类型只有一个实例（一个 LLM worker pool、一个 agent pool），不需要 instance 编号

### 心跳超时判定

```
heartbeat_timeout(name):
  last_hb = kv.Get("/sys/rwir-backend/<name>/heartbeat").Int()
  if now - last_hb > 15s:
    kv.Set("/sys/rwir-backend/<name>/status", "offline")
    return true
  return false
```

后端每 5s 更新 heartbeat。kvlang 在每次 Select 时惰性检查——不额外维护扫描 goroutine。

## 负载模型

三类后端的负载含义不同：

| 类别 | load 含义 | 更新方式 |
|------|----------|---------|
| compute | 活跃 GPU stream 数 / 最大 stream 数 | 后端每次接收任务时 ++、完成时 -- |
| api | 进行中的 HTTP 请求数 / 并发上限 | 同上 |
| agent | 运行中的 sub-agent 数 / worker 上限 | 同上 |

负载是后端的**自报值**——kvlang 不计算负载，只读取并取最小值。这避免了 kvlang 需要理解每种后端的容量模型。

## 与现有 `/sys/op/` 的关系

现有 `/sys/op/<backend>/<n>/` 用于单 tensor op 调度（`dispatch.Compute` 当前路径）。

**共存策略**：`/sys/rwir-backend/` 不替代 `/sys/op/`。两者服务不同粒度：

| | `/sys/op/` | `/sys/rwir-backend/` |
|--|-----------|---------------------|
| 粒度 | 单 op | rwir 指令（可为单 op 或多指令 block） |
| 路由 | backend + instance 两级 | 后端名一级 |
| 淘汰 | 保留，op-gpu 短期仍走此路径 | 长期统一入口 |
| 迁移 | — | op-gpu 成熟后从 `/sys/op/` 迁移到 `/sys/rwir-backend/` |

## keytree 路径常量

```go
// keytree/sys.go

const SysRwirBackendRoot = "/sys/rwir-backend"

func SysRwirBackend(name string) string {
    return SysRwirBackendRoot + "/" + name
}
func SysRwirBackendStatus(name string) string {
    return SysRwirBackend(name) + "/status"
}
func SysRwirBackendOp(name, opcode string) string {
    return SysRwirBackend(name) + "/op/" + opcode
}
func SysRwirBackendCmd(name string) string {
    return SysRwirBackend(name) + "/cmd"
}
```
